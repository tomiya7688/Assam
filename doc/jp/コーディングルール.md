# ASSAM コーディングルール

言語: 日本語 | [English](../en/coding-rules.md)

人間および AI エージェント（Claude Code / Codex / ChatGPT / Copilot）を含む全ての貢献者が必ず従う。違反は PR のセルフレビューで修正してからマージする。

## 構造

- 1ファイルにつき1クラス。
- 各クラスの責務は1つ。
- 機能とそのテストを、焦点の絞られた1単位として扱う。
- 1つの PR は1機能（または1つの文書変更）に限定する。無関係な整形・リネームを混ぜない。

## Python

- 対応バージョンは `pyproject.toml` の `requires-python`（3.10 以上）。それより新しい構文や標準ライブラリに依存しない。
- 新規モジュールは `from __future__ import annotations` と1行のモジュール docstring で始める。
- 外部依存を追加しない（標準ライブラリのみ。テストは pytest）。
- 不正な入力は `ValueError`（検証系）または `VMError`（VM 実行時）で明示的に失敗させる。暗黙の補正・黙った近似をしない。
- 命令の仕様（オペランド、効果、trap、マッピング ID）は `assam/data/instruction_registry.json` を唯一の情報源とし、コードに重複して持たない。
- JSON データを変更したら、対応する `assam/data/*.schema.json` との整合を保つ。

## テスト

- 変更した振る舞いには必ずテストを追加する。バグ修正は再現テストを先に書く。
- 実装ファイル `assam/<name>.py` に対しテストは `tests/test_<topic>.py`。
- テストは決定的であること（時刻・乱数・ネットワーク・ホスト固有パスに依存しない）。
- 検証していない項目を完了扱いにしない。ターゲット変換表のチェッカーは構造・参照・網羅の検査のみで、意味の等価性は検証しない。

## 文書

- 日本語が正本。英語版は同じ変更で同期する。未決事項は両言語で「未決」と明記する。
- 仕様・README・開発予定は、挙動を変える PR で同時に更新する。
- 完了した項目は開発予定でチェックを付けるか削除する。

## Git

- コミットは機能単位。メッセージは命令形の1行要約＋必要なら本文。
- 秘密情報・認証情報・生成物・`__pycache__` をコミットしない。
- 他の貢献者の未コミット変更や無関係な変更を、確認せず巻き込まない・上書きしない。
