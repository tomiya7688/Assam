# ASSAM v1 命令セット仕様

言語: 日本語 | [English](../en/instruction-set.md)

この文書はPython VMで実行するASSAM v1の構文、命令、検証規則、エラー動作を定める。

## プロファイル

- `core` は移植先へ機械的に対応付けるための小さな低水準命令層。
- `full` はCore命令に加え、ASSAM VM専用の便宜命令・端末操作を含む。
- `Push` / `Pop` と端末操作命令は `full` のみで有効。端末操作はCoreの命令ではない。
- VMと解析器は明示profileを受け取り、未指定ならJSON IRのprofile印を使う。印がない従来プログラムは `full` として扱う。
- 命令名、別名、オペランド形式、実行ハンドラ、レジスタ読み書き位置、ゲストデータメモリ効果、trap条件、制御フロー分類は [命令レジストリ](../../assam/data/instruction_registry.json) を共通定義とし、Parser、C入力変換器、VM、解析器が参照する。Core命令の `target_mapping_id` は将来のターゲット対応表が参照する名前空間付きhook IDで、対応表の存在や網羅性を意味しない。`read_operands` / `write_operands` はオペランド位置を示す。`data_memory_effects` はゲストからアドレス指定可能なデータメモリだけを表し、VM内部スタックと端末バスは別扱いとする。整数データを扱うCore命令は `integer_parameters` に対象入力位置を記録し、結果位置は `write_operands` で示す。幅と符号は `not_decided` のままであり、実行意味を確定するものではない。JSONの `schema_version` はレジストリ形式の版で、Coreプロファイル自体は引き続き Draft。

### プロファイル別の命令

`core` の現行命令一覧は `Move`, `Load`, `Store`, `Add`, `Subtract`, `Multiply`, `Divide`, `Modulo`, `And`, `Or`, `Xor`, `Not`, `ShiftLeft`, `ShiftRight`, `Compare`, `Jump`, `JumpEqual`, `JumpNotEqual`, `Call`, `Return`, `Halt` です。これはPython実装が現在受理する一覧であり、Core仕様の最終確定を意味しません。

`full` はこれらに加え、`Push`, `Pop` と仮想端末操作を受理します。CLIの `--profile core` はこの境界への適合性を検証します。アーキテクチャ変換や整数幅・呼出規約は別途仕様化が必要です。

## JSON IRのプロファイル印

- JSON IR全体の形は [program-ir-v1.schema.json](../../assam/data/program-ir-v1.schema.json) で検証できる。profile印なしの既存JSONも許容する。
- Schemaは構造検証用で、命令名・オペランド・ラベル参照の意味検証は `InstructionSet` が別途行う。
- JSON IRを読み込む `Program.from_dict` / `Program.from_json` は `labels` を文字列名から整数の命令添字への辞書として検証する。名前は空でなく、添字は `0` 以上かつ命令数未満（末尾位置は不可）とし、boolや文字列の添字も `ValueError` で拒否する。これはロード時の境界検証であり、分岐先オペランドの意味検証は引き続き `InstructionSet` が行う。
- `json --profile core` は命令をCoreとして検証し、JSON IRのトップレベルに `profile` オブジェクトを付ける。
- 印にはプロファイル名、版、命令レジストリschema版を記録する。現在の版文字列 `draft` は安定版の保証ではない。
- 現行形式は `{"profile":{"name":"Assam Core","version":"draft","registry_schema_version":2}}`。
- このprofile印のJSON Schemaは [assam-core-profile-draft.schema.json](../../assam/data/assam-core-profile-draft.schema.json)。
- opcode/operandと効果の共通定義は [instruction_registry.json](../../assam/data/instruction_registry.json)、その形式は [instruction-registry-v2.schema.json](../../assam/data/instruction-registry-v2.schema.json) で表す。
- 印のあるIRは `run` / `analyze` が既定でそのプロファイルを使う。明示指定が印と異なる場合は拒否する。
- 印のない既存JSON IRは後方互換のため `full` として扱う。

## 基本形式

- 1行に1命令を書く。命令名は大文字・小文字を区別しない。
- オペランドは空白またはカンマで区切る。`;` 以降はコメント。
- ラベルは `name:` の形式で、ジャンプ先にはラベル名を指定する。
- 整数は10進または `0x` 形式。レジスタは `r0` から `r15`。
- レジスタを取る位置では即値またはレジスタを指定できる。`r` と数字だけの文字列はレジスタとして解釈する。
- 比較結果は等しい場合 `1`、異なる場合 `0`。
- Divideは0方向への整数除算。Moduloは `x - Divide(x, y) * y` で定義する。
- 現行VMは選択した算術命令だけを評価する。Add・Subtract・Multiplyの右辺0は有効で、Divide・Moduloの右辺0は `VMError` となる。これは現行実装の挙動であり、Core整数幅・符号の正式仕様は未決。
- Load/StoreはVM内の疎なメモリを使い、未書き込みアドレスのLoadは `0` を返す。
- 命令名、ラベル、オペランド数、オペランド形式、レジスタ範囲、分岐先をVM作成時に検証する。不正プログラムは実行開始前に `ValueError` で拒否する。
- レジストリの `trap_conditions` は、現行Python VMで観測される命令固有のゼロ除算、負のシフト量、Callスタック不足を記録する。Full専用のPopにはデータスタック不足も記録する。これはDraft Coreの規範的なtrap意味を確定しない。端末バスやホスト環境由来のエラーはこの分類に含めない。
- 実行中のtrapと端末通信エラーは、命令位置を含む `VMError` として報告する。

## 命令一覧

| 命令 | オペランド | 動作 |
|---|---|---|
| Move | `register, value` | 値をレジスタへ代入 |
| Load | `register, address` | メモリから読み込む |
| Store | `address, value` | メモリへ書き込む |
| Add / Subtract / Multiply / Divide / Modulo | `register, integer, integer` | 整数演算 |
| And / Or / Xor | `register, integer, integer` | ビット演算 |
| Not | `register, integer` | ビット反転 |
| ShiftLeft / ShiftRight | `register, integer, integer` | 整数を指定ビット数シフト |
| Compare | `register, value, value` | 等価比較 |
| Jump | `target` | 無条件分岐 |
| JumpEqual / JumpNotEqual | `target, value, value` | 等値・不等値で分岐 |
| Call / Return | `target` / なし | 呼び出し・復帰 |
| Push / Pop | `value` / `register` | データスタック操作 |
| Halt | なし | VMを停止 |
| CreateTerminal / DestroyTerminal | `name` | 仮想端末を生成・破棄 |
| ConnectTerminal / DisconnectTerminal | `name, name` | 端末間接続を変更 |
| Send | `sender, recipient, value` | 接続先へメッセージを送信 |
| Broadcast | `sender, value` | 接続中の全端末へ送信 |

`Push` / `Pop` と `CreateTerminal` 以降の端末命令はフルプロファイル専用。

`mov`, `j`, `je`, `jne`, `ret`, `stop`, `shl`, `shr` は対応する命令の別名。

## エラー規則

- 未知命令、不正なオペランド数、範囲外レジスタ、未定義ラベルはVM生成時に拒否する。
- 命令位置とソース行が分かる場合は、その位置をエラーメッセージに含める。
- 実行時エラーでは命令ポインタと命令を含む `VMError` を送出する。
- fullプロファイルの端末命令における未登録端末、重複登録、未接続送信は端末操作エラーとし、命令添字、ソース行（ある場合）、命令名、理由を付けた `VMError` に変換する。拒否された操作は端末・接続・メッセージの状態を変更しない。端末バス内部の想定外の `KeyError` はこの変換対象に含めない。
- `trap_conditions` の省略は、現行レジストリで命令固有trap条件を分類していないことを表す。ステップ上限など実行環境の制限は命令trapとは別である。
- `VM.run(max_steps=N)` と `Debugger.continue_execution(max_steps=N)` の上限は呼び出しごとの実行命令数。N命令目の `Halt` は成功し、未停止でN命令を実行し終えた場合は次の命令を実行せず、それぞれ `VMError` / `RuntimeError` を送出する。`N=0` でも停止済みなら現在の状態を返す。負数・整数以外・boolは実行前に `ValueError` で拒否する。
