# ASSAM 開発ワークフロー

この文書は、一回分の作業を完了させる手順を定義する。

## 1. 作業開始

- `doc/開発予定.md` と関連仕様を確認し、対象を一機能に限定する。
- `git status` で既存変更を確認し、無関係な変更を保持する。
- 作業開始前に必ずリモートの変更を取り込む。

```text
git fetch origin
git pull --rebase origin <現在のブランチ>
```

競合が発生した場合は解決してからテストを再実行し、取り込みに失敗した場合は実装を開始しない。

## 2. 実装と検証

- 既存APIとテストを確認して実装する。
- 今回の機能に対応するテストを追加する。
- 関連テスト、CLI、VM、JSON、端末通信を必要に応じて検証する。
- 未検証の項目を完了扱いにしない。

## 3. 記録と完了

- README・仕様書・開発予定を必要に応じて更新する。
- 今回の作業内容、検証結果、未解決事項、次回対象を記録する。
- 差分を確認し、機能単位でコミットする。
- 共有する場合はリモートへプッシュし、ブランチとコミットを確認する。

一回分の完了条件は、リモート変更の取り込み、実装、テスト、必要な文書更新、Git記録、未完了事項の記録がすべて完了していることである。
